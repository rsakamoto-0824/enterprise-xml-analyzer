## Excelと配布の確認範囲

単体テストではExcelJSで生成ファイルを開き直し、値・型・シート分割・文字列保持を確認しています。代表的な抽出結果と差分結果をopenpyxlでも読み直し、各1シート、数式・セルエラー・外部リンク・VBAが0件であること、先頭ゼロ、日本語、フィルター、固定行を確認しました。LibreOfficeでPDFに変換して全6ページを目視確認し、印刷は列方向に分割されますが値の欠落はありませんでした。元のXLSXは変換で上書きしていません。Excelの実アプリではファイル選択画面の「開く」が無効になり、ブックを開く検証を完了できませんでした。原因は未特定です。Windows版Excelでの修復警告・表示・保存再オープンは受入検証として残します。

IIS用web.configのXML構文、9配信ファイルのSHA-256、4種類のWorker、公開領域へのソース・テストXML・ログの混入がないこと、ZIP整合性を確認しました。PowerShellのWindows実行、実IISの認証・HTTPS、社内CA、UNC、Windows版Edge/Excel、Windowsの125%/150% DPI、ElectronのWindows実行は未検証です。[IIS受入手順](IIS-deployment.md)に従って会社環境で確認してください。

## 依存パッケージ監査

`npm audit --omit=dev` は既知の指摘0件でした。開発依存を含めると低リスク4件が残っています（browserifyの間接依存elliptic等）。ExcelJSはブラウザ同梱版をそのまま使わず、修正版uuid 11.1.1を固定して再構築し、cryptoポリフィルを除外します。依存監査で0件でも安全性を保証するものではありません。ビルド警告・Windowsでの再検証は [既知の制限](limitations.md) を参照してください。
