# Pythonスタンドアローン版の構成

2026年10月25日の「Windowsでバージョン依存により使用できないため、Python 3.14.6で作り直す」という指示を優先し、主な配布方式をIIS/Electronからネイティブのデスクトップアプリへ変更しました。旧版の具体的なエラーログは未提供のため、旧版の失敗原因を特定済みとはしていません。

## 実装

- `run.py`: Python 3.14.6の厳密確認、GUI起動、同梱版の自己検証。
- `xml_analyzer/gui.py`: 日本語の7画面、バックグラウンド処理、メインスレッドだけでTk操作。
- `parser.py`: Expatへ64KiBずつバイナリ入力。UTF-8/UTF-16、Namespace、コメント・PI・CDATAを保持。
- `storage.py`: SQLiteのファイル・親・パス索引、作業ファイルのbackup API保存。
- `comparison.py`: 親スコープ内の一意キー、ハッシュ、一意名、兄弟順による段階対応。曖昧な繰り返しを明示。
- `extraction.py`: レコード解決、パス・列・型・繰り返し・条件、100行プレビュー、旧JSON移行。
- `simple_export.py`: 詳細設定を使わず全XMLの全要素を一覧化。親・空要素を含む。パスは深さ分のスタックで構築し、直下のテキスト・CDATAをDBから逐次取得。長い値をUTF-16単位で継続行へ分割。
- `writers.py`: OOXMLのシートXMLを一時ファイルへ逐次書き込み、ZIP化するXLSX。CSVも逐次保存。
- `visualization.py`: Tk Canvasによる部分グラフ、SVG、Windows GDIによる表示範囲PNG、XML断片。
- `windows.py`: DPI設定、ネイティブファイルドロップ。外部DLLはWindows標準APIのみ。
- `build_windows.py`: CPython 3.14.6を同梱するWindows x64配布フォルダとZIPを作成。

実行時のpip依存はありません。画面・DB・XMLパーサーはCPython完全版の標準構成を使います。PyInstallerとその依存はビルド専用で、バージョンとwheelハッシュを固定します。標準ライブラリのバイナリ依存（Tcl/Tk、SQLite等）はPython配布に含まれるものを同梱するため、OSとPython配布元の差はテストで確認します。

## 大容量と安全性

XML全体をメモリへ読みません。開いている要素のフレーム、最大1Mi文字の単一テキスト、1チャンク分と限定された候補だけを保持します。未完了トークンが4MiBを超えた場合は停止し、巨大な開始タグも無制限に蓄積しません。XMLは深さ256、名前種類1万で制限します。

SQLiteは1チャンク単位でコミットし、キャンセル時は対象ファイル単位で削除します。SQLite操作を行うスレッドごとに接続し、Tkのスレッドに解析結果を直接渡して描画しません。スレッド間は進捗と完了通知だけをQueueで渡します。

XLSXは共有文字列表を全メモリへ保持せずinlineStrを使います。シートXMLはディスクへ逐次出力し、シートを最大16ハンドルまで開いて管理します。最終ZIPを置換するまで既存出力を保持します。保存先に一時XML・ZIPのための空き容量が必要です。

XML文字列はTkの文字表示へ渡し、HTMLとして実行しません。DTDと外部エンティティを拒否し、独自エンティティの展開も行いません。XLSX文字列は明示的な文字列セル、CSVでは数式先頭をアポストロフィで保護します。ログは処理名・時刻・所要秒・ランダムなファイルID・結果に限定し、ファイル名とXML値を含めません。

## 比較の意味と上限

同じ親の一意キーで対応した兄弟の位置変更だけをMOVEDとします。別親への移動は追加・削除になります。前方への挿入で位置が変わったキー付き兄弟もMOVEDになる場合があります。4096件を超える兄弟候補はページ単位の暫定対応としてAMBIGUOUSとします。曖昧な場合も下位を比較できますが、一意な同一性を保証しません。

ハッシュ省略は比較設定がハッシュ生成条件に合う場合だけ使用します。厳密照合は全ノードを直接比較します。構造比較で省略した範囲は要素数、完全・値比較の省略範囲は文書ノード数で集計します。省略範囲の文書ノード数には対象外のコメント等が含まれる場合があるため、独立した要素の変更率とは異なります。

グラフは500ノード・深さ4、ツリーは250件ずつ・表示合計1万、検索保持1万件・画面1000件、差分表示1000件ずつ。繰り返し値・行展開は1レコード1万件、出力合計200万行、シート512枚。Excelは1シート1048575データ行・16384列・1セル32767 UTF-16単位です。数値はExcelの15桁精度を超える場合に停止し、文字列型の利用を案内します。

任意XPath式、グローバル移動、元XMLのバイト列復元、グラフ全体のPNG保存には対応しません。PNGはWindowsで現在表示されている範囲です。SVGは現在読み込んだ部分グラフ全体を保存します。

## 全要素一覧（v2.1.0から継続）

読み込み済みの全XMLを対象に、`kind='element'` の各行を文書順に取得します。ツリー・グラフ・検索・100行プレビュー・候補列の表示上限には依存せず、詳細出力の列・条件・対象選択・型も参照または変更しません。ファイル名が同じ場合もファイルIDと要素番号で識別できます。

直下のtext/CDATAだけを順に連結し、子孫テキストの重複出力を避けます。混在コンテンツを原文XMLの並びへ復元する用途ではありません。属性は既存のNamespace展開名をキーとするJSONで、Namespace宣言そのものは属性へ追加しません。

親要素と空要素も原則1行です。長い要素名・Namespace・パス・属性JSON・直接テキストは32767 UTF-16単位を上限に分割し、サロゲートペアを壊しません。各継続行はファイル名・ファイルID・要素番号・親番号・階層を繰り返し、残る5列は分割した続きの値と分割番号を保持します。全文を親ごとに蓄積せず、DBカーソルとセル1個分のバッファを使用します。200万出力行の上限・中断・成功時だけの置換は既存writerを共用します。

## 機械学習向け簡単出力・サイズ変更（v2.2.0）

`ml_export.py` は2回の逐次走査で学習表を作成します。最初の走査で全件の項目・繰り返し・型・欠損数・定数列候補を確定し、2回目で型付きの値をwriterへ渡します。SQLite接続は処理スレッド内で再利用し、全レコードをリストとして保持しません。プレビューは全件の型確認後に先頭20件・30列・各80文字だけ表示します。保存は全件・全列です。

自動候補は各XMLに存在し、少なくとも1ファイルで複数回現れるパスのうち最も浅いものです。同じ深さでは総件数の多い順、パス順で選択します。候補一覧は100パスまでで、入力による変更も可能です。繰り返しが共通しなければファイル単位に切り替えます。明示したパスが1ファイルでも存在しない場合は停止し、黙って除外しません。候補検出はデータの意味を判断しません。

選んだ要素の配下の属性・葉の値・混在コンテンツの直接テキストを出力します。名前空間はURI展開名で区別し、要素の接頭辞が違っても同じURIなら同じ列です。繰り返し番号は同じ名前空間・名前の兄弟順であり、別レコード内の意味的対応は保証しません。直積、平均、行削除、前処理、学習は実行しません。

全件で数値へ変換可能な列だけ数値化し、true/falseは真偽値とします。先頭ゼロ、ID/code/serial等の候補、Excelの15桁精度外の値は文字列です。混在型は文字列、欠落・空文字・空白のみは空欄です。日付は文字列です。ID候補は命名による目印であり、利用者の判断が必要です。目的変数は辞書の役割だけに記録します。

1件1024列・4Mi UTF-16単位、1セル32767 UTF-16単位が上限です。学習用の観測を継続行に分割しません。全件型推定中や保存中に失敗・中断した場合は既存保存先を保持します。出典は元ファイルごとの論理データ連番範囲で、シート分割後も学習シートを順に連結した行順に対応します。補助シートも全体200万行の上限に含みます。

`layout.py` のFlowFrameが要求幅に応じてツールバーを折り返し、ScrollablePageが各画面の縦スクロールを管理します。幅900未満はタブを上部の選択欄に切り替え、640×480を最小寸法とします。表の縦横スクロール・詳細設定の横スクロールは独立します。Tkオブジェクトの循環参照は処理開始前にUIスレッドで回収し、バックグラウンド処理でTkを解放しないようにします。

128文字を超える列名は `項目_番号` に短縮し、既存名との衝突時は番号と連番を付けて一意にします。短縮前のXML相対パスは項目定義シートに保持します。
